# 输入方案与模型自动升级设计

基线：CI86 / `e4865f604dc64fce9db68cc8af1ff2db67369f45`。

本文定义输入方案、共享依赖和语言模型的更新检测与实施规则。它不负责
Weasel 程序自身的版本更新，也不改变用户现有的 Rime 自定义文件。

## 1. 设计目标

1. 内置万象拼音 Lite 可以独立跟随万象官方稳定版本更新。
2. 已验证方案在不影响输入体验的情况下完成检查、下载、安装和重新部署。
3. 用户提供的 HTTPS 更新源可以持续检查，但必须具备可验证的版本清单。
4. 普通 ZIP 地址只执行一次安装；本地导入包默认不检测更新。
5. 用户修改、同名文件冲突、兼容性变化和部署失败均不能导致静默覆盖。
6. 新旧文件、共享依赖和模型必须作为一个事务提交或全部回滚。
7. 普通用户使用默认设置即可保持安全、稳定和及时更新。

## 2. 来源分类与默认行为

| 来源 | 标识 | 默认检测 | 默认安装 |
|---|---|---|---|
| 内置已验证目录 | `curated_catalog` | 自动 | 兼容且无冲突时自动 |
| 用户确认的签名更新源 | `signed_feed` | 自动 | 默认自动，可按方案关闭 |
| 普通 HTTPS ZIP | `direct_archive` | 不自动 | 仅本次安装 |
| 本地 ZIP | `local_import` | 不自动 | 仅本次安装 |
| 既有 Rime 文件 | `existing_unmanaged` | 不检测 | 不接管、不卸载 |
| Weasel 基础方案 | `builtin_distribution` | 随完整安装包 | 不独立更新 |

本地 ZIP 如果包含作者声明的签名更新源，安装完成后可以询问用户是否
“跟随作者更新”，但默认保持关闭。普通 HTTPS ZIP 即使响应头发生变化，也
只能提示“文件可能已变化”，不能自动替为新版本。

## 3. 更新清单与签名

可信更新源提供一个版本化 JSON 清单和一个分离签名文件。客户端对清单的
原始 UTF-8 字节计算 SHA-256，并通过 Windows CNG 验证
`ECDSA_P256_SHA256` 签名。

内置目录公钥随 Weasel 发布并固定在程序中。用户提供的签名源第一次使用时
显示域名、发布者名称和公钥指纹；用户确认后把公钥指纹固定到本地安装记录。
后续清单必须使用同一密钥，密钥轮换必须由旧密钥签署。

清单至少包含：

- `feed_id` 和单调递增的 `feed_sequence`；
- `package_id`、显示版本和 `release_sequence`；
- 稳定版或预览版通道；
- 下载 URL、文件大小和 SHA256；
- 精确文件清单 URL 及其 SHA256；
- Weasel 与 librime 的兼容范围；
- 兼容模型版本；
- 是否存在不兼容变化；
- 被替代、停止维护或撤回状态。

客户端保存每个更新源已接受的最高 `feed_sequence`，并保存每个包已接受的
最高 `release_sequence`。自动流程拒绝序号回退；用户主动恢复旧版本使用
单独的本地回滚流程，不降低已记录的最高远程序号。

数据结构见：

- `package-update-feed.schema.json`；
- `scheme-catalog.schema.json`；
- `package-content-manifest.schema.json`。

## 4. 用户提供 HTTPS 地址的识别

用户粘贴地址后先发送受限的 HTTPS 请求，并按响应类型处理：

1. 若内容符合 `package-update-feed.schema.json`，进入签名源确认流程；
2. 若内容是 ZIP，作为一次性安装包处理；
3. 若 ZIP 内含 `weasel-package.json` 和 `update_feed`，安装后再询问是否启用；
4. 其他内容、HTTP 地址、跨协议重定向或无法确定的格式直接拒绝。

`ETag`、`Last-Modified`、Content-Length 和最终 URL 只用于缓存及诊断，不能
代替签名、版本序号或 SHA256。

## 5. 检查计划

默认开启“自动保持方案最新”，仅作用于已验证目录和用户确认的签名源。

- WeaselServer 启动后延迟 5 至 15 分钟触发轻量检查；
- 每个更新源 24 小时最多自动检查一次；
- 延迟加入稳定的本地抖动，避免所有客户端同时请求；
- 手动“立即检查”不受 24 小时限制；
- 离线、代理失败和临时服务器错误采用指数退避；
- 检查失败不弹出打断输入的窗口，只在设置页显示状态；
- 发现需要用户处理的不兼容更新或冲突时发送一次通知。

不新增常驻 Windows 服务或计划任务。WeaselServer 只负责按时间启动隐藏的
`WeaselDeployer.exe /package-update-check`；所有网络、校验、文件写入和部署
仍由 Deployer 执行。

## 6. 版本与兼容性判断

显示版本只用于界面。自动更新顺序以 `release_sequence` 为准，避免
`17.10`、日期版本或带文字版本的字符串比较错误。

候选更新必须同时满足：

1. `release_sequence` 高于当前已安装版本；
2. 更新通道符合用户设置；
3. 当前 Weasel 和 librime 位于兼容范围内；
4. 方案所需模型和共享依赖存在可组成一致事务的兼容版本；
5. `schema_id` 没有与其他来源发生重复；
6. 所有目标文件通过同名文件预检；
7. `breaking_change` 为 `false`。

不兼容更新、方案标识迁移和 `breaking_change: true` 只显示通知，不自动安装。
用户可以跳过单个 `release_sequence`，也可以固定当前版本。

## 7. 模型更新规则

- 未安装的可选模型不参与自动下载；
- 用户安装模型后，默认跟随与当前方案兼容的稳定模型；
- 模型与方案存在兼容关系时，必须在同一更新计划中解析；
- 420 MB 级模型默认仅在非计费且非漫游网络后台下载；
- 替换前检查可用空间至少容纳新文件、事务备份和安全余量；
- 模型安装失败不影响无模型状态下的方案正常输入；
- 模型被用户替换或修改后暂停自动更新并显示“文件已修改”。

## 8. 后台下载

下载使用每用户 BITS 任务，优先级为 Background：

- 支持断网、注销前中断和重启后恢复；
- 默认禁止在漫游或受限计费网络自动下载；
- 下载到实际 Rime 用户目录下的私有 `.weasel-packages` staging 目录，扩展名
  使用 `.part`，确保最终替换发生在同一卷；
- BITS 任务名包含固定产品前缀和内部包 id；
- 下载完成回调只能启动已安装目录中的固定 `WeaselDeployer.exe`，并使用固定的
  内部完成参数；Deployer 按固定任务名重新枚举并接管任务；
- Deployer 启动时重新枚举未完成任务，恢复丢失的进度和完成通知；
- 成功后调用 Complete，永久错误或用户取消后调用 Cancel，避免遗留任务。

清单和小型元数据可使用 WinHTTP；方案包和模型使用 BITS。任何下载均不调用
浏览器、不执行远端脚本，也不使用 GitHub 备用地址。

## 9. 下载后校验

下载结束后依次检查：

1. 最终 URL 和协议；
2. 声明长度；
3. 压缩包或模型 SHA256；
4. ZIP 中央目录、路径穿越、ADS、重解析点、重复路径和解压上限；
5. 精确文件路径、大小和逐文件 SHA256；
6. 受保护文件；
7. Lua 等可执行配置能力；
8. schema、词典、Lua 和模型之间的引用闭包。

校验失败立即删除 staging 内容，保持当前方案不变。

## 10. 同名文件和共享依赖

目标路径按 Windows 不区分大小写规则规范化后，与
`file-ownership-index.schema.json` 比较：

- 路径不同：正常安装；
- 路径相同、摘要相同：增加所有者引用，不重复覆盖；
- 路径相同、摘要不同：默认阻止；
- 用户已修改：保留并暂停相关更新；
- 多个方案共享的文件发生变化：所有受影响方案必须在同一事务中升级到相同
  摘要，否则阻止更新。

更新器不自动重命名 YAML、词典或 Lua 文件，也不通过改变搜索路径隔离方案。

## 11. 安装和重新部署事务

检查、下载和解压阶段不进入 maintenance。写入阶段执行：

1. 创建更新计划并再次确认清单未变化；
2. 获取 `WeaselDeployerMutex`；
3. 通知 WeaselServer 进入 maintenance；
4. 记录方案选择、所有权索引和目标文件当前摘要；
5. 把即将替换的文件放入本次事务备份目录；
6. 从同卷 staging 使用原子替换提交全部文件；
7. 更新方案安装记录、所有权索引和选择列表；
8. 调用现有 `Configurator::UpdateWorkspace(true)` 等价路径；
9. 确认部署成功、更新后的 schema 可发现且当前已选方案仍存在；
10. 提交事务并恢复 WeaselServer。

任一步失败均恢复目标文件、所有权索引和方案选择，再部署旧状态。回滚也失败
时保留完整事务目录和日志，并提示用户执行“修复方案”，不能把失败状态标记
为安装成功。

## 12. 内置版本与用户层更新

安装包中的 Lite 是始终可用的只读基线。独立下载的新版本安装到实际
`WeaselUserDataPath()`，通过 Rime 用户层覆盖内置版本，并记录为受管理文件。

每次完整 Weasel 升级后执行协调：

- 用户层版本较新：继续保留；
- 两层版本和文件摘要完全相同：移除冗余用户层受管理文件，回到内置版本；
- 新安装包内置版本较新：在没有用户修改和固定版本时移除旧用户层覆盖；
- 用户固定版本：继续保留并在设置页显示“已固定”；
- 用户层文件已修改：保持文件并停止自动协调。

“恢复内置版本”只删除属于该方案且仍与安装记录摘要一致的用户层文件，不删除
共享文件、用户词典或任何 `*.custom.yaml`。

## 13. 用户界面

页面顶部提供：

- `自动保持方案最新`，默认开启；
- 说明文字：“只自动安装来自已验证来源的兼容版本”；
- `立即检查更新`。

每个方案显示当前版本、来源、更新通道和状态，并提供：

- 自动更新开关；
- 暂停更新；
- 跳过此版本；
- 固定当前版本；
- 查看更新说明；
- 恢复内置版本；
- 更新记录。

普通状态只显示“已是最新版本”。下载进度只在下载发生时出现。用户需要处理
时使用明确状态：用户文件已修改、共享依赖冲突、版本不兼容、发布者已变化、
部署失败并已恢复。

## 14. 状态机

每个包使用以下持久状态：

```text
idle
  -> checking
  -> update_available
  -> downloading
  -> verifying
  -> ready_to_install
  -> installing
  -> deploying
  -> installed
```

异常状态为：

```text
paused_user_modified
blocked_conflict
blocked_incompatible
blocked_publisher_change
download_failed
verification_failed
deploy_failed_rolled_back
repair_required
```

每次状态变化原子写入本地记录，程序重启后从最后一个可恢复状态继续。

## 15. 日志与隐私

日志记录包 id、版本、序号、域名、摘要、BITS job GUID、冲突路径和部署结果。
不记录用户词典内容、自定义短语内容、完整本地导入路径或输入内容。本地导入
记录只保留原始文件名，安装完成后丢弃来源绝对路径。

## 16. 测试门槛

- 签名正确、错误、缺失、旧清单回退和密钥轮换；
- 稳定版、预览版、跳过版本、固定版本和停止维护；
- CNB 超时、断网、重启、代理、重定向和计费网络；
- ZIP 地址、签名源地址、本地 ZIP 和既有未托管方案；
- 同名同摘要共享、同名不同摘要阻止和用户修改保留；
- 多方案共享依赖的成组升级与中途失败回滚；
- 方案与模型兼容组合、模型未安装和大模型磁盘空间不足；
- 部署成功、部署失败回滚、回滚失败后修复；
- Weasel 完整升级后内置版本与用户层版本协调；
- 升级前后 schema 选择、`*.custom.yaml`、用户词典和同步目录逐文件不变；
- 卸载一个方案后仍被其他方案引用的共享文件继续存在。

## 17. 实施顺序

1. 完成清单签名验证、版本判断和只读更新检查；
2. 实现 BITS 下载、持久状态和取消／恢复；
3. 实现精确文件清单、所有权索引和冲突预检；
4. 实现原子安装、自动部署和回滚；
5. 接入内置万象 Lite 与模型；
6. 接入用户签名源、普通 ZIP 和本地导入；
7. 完成设置页状态、历史记录和修复入口。

第一阶段只能报告可用更新，不写入用户数据；后续阶段逐层开放下载和安装，
便于每一步独立验证。
